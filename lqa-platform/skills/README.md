# 技能库（Skill）

领域测试知识包。每个技能是 `skills/` 目录下的一个文件，保存团队反复用到的领域检查要点；生成用例时勾选的技能会被注入 AI 提示词（system + user 双通道），让模型在通用规则之外，还掌握你的业务/项目特定知识。

## 字段结构

无论哪种格式，读入后都归一化为同一结构：

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | 自动 | 文件名（不含扩展名）；界面创建时自动生成 slug，**不要手工改成含路径分隔符的值** |
| `name` | 是 | 技能名称 |
| `body` | 是 | 检查点正文，原样注入提示词——请写成「可执行检查点」而非背景描述 |
| `description` | 否 | 一句话说明用途 |
| `tags` | 否 | 标签，便于检索 |

## 支持格式

| 格式 | 扩展名 | 依赖 |
|------|--------|------|
| JSON | `.json` | 无（界面新建的默认格式） |
| Markdown | `.md` | 无：front-matter 写元数据，正文写 `body` |
| YAML | `.yaml` / `.yml` | 装有 PyYAML 才注册；未安装则该格式被忽略（不引入硬依赖） |

> 界面新建目前固定写 JSON；`.md` / `.yaml` 文件直接放入 `skills/` 目录即可被读取、参与生成与编辑，无需改代码。

```json
// skills/season-pass.json
{
  "id": "season-pass",
  "name": "赛季通行证测试要点",
  "description": "赛季体系的边界与时效检查",
  "body": "- 赛季结算边界：跨月最后一天 23:59 的归属判定\n- 奖励领取时效：过期后是否补发",
  "tags": ["赛季", "商城"]
}
```

```markdown
<!-- skills/season-pass.md（与上面等价） -->
---
id: season-pass
name: 赛季通行证测试要点
description: 赛季体系的边界与时效检查
tags: 赛季, 商城
---

- 赛季结算边界：跨月最后一天 23:59 的归属判定
- 奖励领取时效：过期后是否补发
```

```yaml
# skills/season-pass.yaml（与上面等价）
id: season-pass
name: 赛季通行证测试要点
description: 赛季体系的边界与时效检查
tags: [赛季, 商城]
body: |
  - 赛季结算边界：跨月最后一天 23:59 的归属判定
  - 奖励领取时效：过期后是否补发
```

## 格式规则（同一 id 是一个逻辑实体）

- **读取 / 列举**：同一 id 的多个格式文件并存时，按 `json > md > yaml` 取第一个，列表中去重为一条
- **新建**：该 id 在任一格式下已存在即视为冲突（HTTP 409）
- **更新**：写回原文件所在格式，不会把 `.md` 迁移成 `.json`
- **删除**：清掉该 id 的全部格式文件（幂等）
- **坏文件**：解析失败的文件被跳过，不影响其余技能（与坏 JSON 行为一致）

## 使用方式

1. 界面左侧「技能库」页面：新建 / 编辑 / 复制式修改 / 删除
2. 「生成向导」的「领域技能」区勾选需要注入的技能（可多选叠加）
3. 仅在勾选「启用 AI 补强」时生效——规则模式不读提示词

本目录不预置任何业务知识，代码里也不硬编码领域内容，全部由使用者在界面创建；目录随 git 跟踪，可共享给团队。

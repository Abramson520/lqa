# skills

领域测试知识包（Skill）。每个技能是一个 `skills/` 下的文件，保存了团队反复用到的
领域检查要点；生成用例时勾选的技能会被注入 AI 的提示词（system + user 双通道），
让模型在通用规则之外，还掌握你的业务/项目特定知识。

## 文件格式

支持三种格式，读入后归一化为同一结构（`id` / `name` / `description` / `body` / `tags`）：

| 格式 | 扩展名 | 说明 |
|------|--------|------|
| JSON | `.json` | 默认落盘格式（git diff 友好） |
| Markdown | `.md` | front-matter 写元数据 + 正文写检查点，人工编写最自然 |
| YAML | `.yaml` / `.yml` | **探测启用**：安装 PyYAML 后才生效，否则该格式被忽略（不引入硬依赖） |

```json
// skills/season-pass.json
{
  "id": "season-pass",
  "name": "赛季通行证测试要点",
  "description": "赛季体系的边界与时效检查",
  "body": "- 赛季结算边界：跨月最后一天 23:59 的归属判定\n- 奖励领取时效：过期后是否补发\n- 跨赛季叠加：未领取道具是否结转",
  "tags": ["赛季", "商城"],
  "updated_at": "2026-10-10 12:00"
}
```

```markdown
<!-- skills/season-pass.md（与上面等价） -->
---
id: season-pass
name: 赛季通行证测试要点
description: 赛季体系的边界与时效检查
tags: 赛季, 商城
---

- 赛季结算边界：跨月最后一天 23:59 的归属判定
- 奖励领取时效：过期后是否补发
- 跨赛季叠加：未领取道具是否结转
```

- `name` / `body` 必填；`body` 会被原样注入提示词，请写成「可执行检查点」而非背景描述。
- `id` 为文件名（不含扩展名），由界面创建时自动生成（英文/数字 slug；纯中文名会退化为
  `skill-<hash>` 形式），**不要手工改成含路径分隔符的值**。
- 目录被 git 跟踪，技能可随仓库共享给团队。

## 格式规则（同一 id 是一个逻辑实体）

- **读取优先级**：同一 id 的多个格式文件并存时，按 `json > md > yaml` 取第一个，列表中去重为一条。
- **更新**：写回原文件所在格式，不会把 `.md` 迁移成 `.json`。
- **删除**：清掉该 id 的全部格式文件（幂等）。
- **新建冲突**：该 id 在任一格式下已存在即视为冲突（HTTP 409）。
- **坏文件**：解析失败的文件被跳过，不影响其余技能（与坏 JSON 行为一致）。

## 使用方式

1. 界面：左侧「技能库」页面新建/编辑/删除；在「生成向导」的「领域技能」区勾选。
2. 仅在勾选「启用 AI 补强」时生效——规则模式不读提示词。
3. 多个技能可叠加，同时注入。

> 说明：本目录不预置任何业务知识内容，代码里也不硬编码领域知识；
> 全部由使用者在界面中创建。YAML 格式需环境装有 PyYAML（`pip install pyyaml`）。
